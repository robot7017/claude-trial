# Claude 试用

这个仓库用来试用 Claude，主要试两件事：**写代码**和**日常询问**。试用结束后，根据效果决定要不要采购。

试用时间：两天，具体日期在群里确认。问题数量不限。

## 怎么提交问题

1. 打开本仓库的 **Issues** 页面，点 **New issue**
2. 选一种模板：
   - **代码问题**：写代码、改代码、排查报错
   - **日常询问**：日常问题
   - **项目任务**：涉及整个项目的较大任务，比如加功能、找 bug、重构、读懂代码结构
3. 按模板填写后提交

一个 Issue 只问一件事。大任务建议拆成几步，分几个 Issue 提，比如先「读懂结构」，再「加功能 A」，再「写测试」。

## 项目内容放在哪里

两种方式都可以：

- **直接放进本仓库**：放在 `projects/<项目名>/` 文件夹里。协作者可以自己提交；不是协作者的，可以把文件发给仓库主人代为上传，或者直接把关键代码贴在 Issue 里
- **放在自己的公开仓库**：在 Issue 里贴链接

> ⚠️ **本仓库是公开的**，放进来的代码、文档和 Issue 内容任何人都能看到。请不要放密码、密钥、个人信息，或不能公开的代码和数据。不能公开的项目，请用第二种方式。

## 用什么模型回答

所有问题统一由 **Claude Opus 5.5**（中等思考强度）自动回答，不需要选择。

## 回复放在哪里

- **日常询问**：在 Issue 下面评论回复
- **代码**：短代码直接贴在评论里；长代码放进 `answers/` 文件夹，文件名以 Issue 编号开头（如 `answers/3-xxx.py`），评论里附链接
- **项目**：改动代码时，在项目所在的仓库开 Pull Request，可以逐行查看改了什么，确认后再合并；分析类的回答写在 Issue 评论里
- **追问**：在同一个 Issue 下继续评论，会在下一轮一起回复

每条回复开头都会注明用的模型。

## 什么时候回复

提交 Issue 或追加评论后，Claude 会自动开始处理，一般几分钟内回复；项目类任务可能要更久。一次做不完的项目任务会先给出第一版，Issue 保持打开。回复完的 Issue 会关闭；如果还有问题，可以继续评论或重新打开。

任何人提的 Issue 都会自动回复。区别在于：

- **仓库协作者**：长代码会作为文件提交到仓库，项目改动会开 Pull Request
- **其他人**：所有回答（包括代码）都写在 Issue 评论里，不会改动仓库

想让回答以文件或 PR 的形式给出，请联系仓库主人把你加为协作者。

## 试用结束后

请从这三个方面评价：

1. 代码能不能直接运行，或者只需要稍作修改
2. 日常询问的回答是否准确、有用
3. 自己平时大概会多常用，适合哪种套餐
